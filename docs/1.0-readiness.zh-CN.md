# MusicServer 1.0 验收记录

更新日期：2026-09-14。候选版本：**1.0.0-rc.1**。普通使用说明见 [第一次和 MusicServer 相遇](getting-started.zh-CN.md)。

## 已实现

| 能力 | 行为与边界 |
| --- | --- |
| 空库与引导 | 14 首初遇歌单、每屏七首，试听 → 喜欢 → 下载结果；状态和偏好存 SQLite，设置可重开。 |
| 下载环境 | 一键准备固定版本，HTTPS、大小、SHA-256、版本及真实音频转换检查通过后原子启用；后台任务最多 10 分钟。 |
| 下载可靠性 | 缺组件不消耗重试次数；已知音源优先，失败后一次搜索回退；外部进程有超时；不以时长替代歌手证据。 |
| 音频完整性 | 独立暂存目录，不删除同名用户文件；检查媒体类型、时长和完整解码；重名入库使用唯一名称。 |
| 失败可处理 | 试听 15 秒上限，重试或换歌；喜欢不会因下载失败丢失；下载动态显示状态与重试入口。 |
| 名称与歌词 | 名称整理是显示偏好；同名歌词优先，联网查词有身份检查、租约与冷却。 |
| 数据恢复 | 一致性备份、升级前备份；停掉 APP 自己拥有的服务后验证备份，保存旧数据，刷新 WAL，再原子恢复；不移动音乐文件。 |
| 诊断 | 组件和操作进度可见；导出允许字段的 ZIP，不含原始日志、歌名、路径、Cookie、音频或数据库。 |

SQLite 仍是唯一运行时真源。快照和诊断只是备份、导出产物。组件固定来源、大小和校验值集中在 `Get-DownloadComponentCatalog`，独立安装在 APP_HOME，不随运行时更新覆盖。

## 本地验证证据

- 21 个正式套件并行分组运行，306 项 Pester 通过，无超时；新增的维护 API、静态资源与后台备份测试随后单独通过。
- JavaScript 行为测试 39 项通过，包括错误恢复、旧试听超时不干扰新歌曲、七首浏览、推荐居中和喜欢状态。
- Rust 13 项通过；真实 Tauri 编译及 NSIS 安装包构建成功。
- 独立 APP_HOME 完成组件下载、SHA-256、版本与实际音频转换验证。
- 真实来源样本：青空 / Candy_Wind，Speed of Light / 塞壬唱片-MSR,DJ OKAWARI,二宮愛，理想三旬 / 陈鸿宇，全部经 NetEase 下载、完整解码和入库。有效轮次约 25、27、35 秒；重新运行 worker 后队列为空，没有重复下载。两首生成相邻歌词文件。
- 最初两次候选搜索暴露了外部进程退出码回归，已修复，并补充已知音源优先的覆盖。三首成功不能推算所有来源的成功率。
- 备份恢复、篡改拒绝、路径穿越拒绝、诊断字段隔离、维护任务终态防覆盖有独立测试。

所有验收数据与用户实际曲库、喜欢记录、Cookie 隔离。

## 发布验收边界

实际 Tauri APP 已验证：移除下载工具 PATH 后，一键准备全部组件；点击喜欢《青空》后约 8 秒完成下载校验、出现在音乐树并成功本地播放；手动备份后将显示模式改为 canonical，恢复后重新启动并回到 raw，同时生成恢复前的安全快照；诊断 ZIP 生成成功，960×640 没有横向溢出。桌面截图位于本地 `output/playwright/v1-care-960.png`。

GitHub 首轮的 api 和 desktop-build 均通过，后者完成干净 Windows 上的静默安装、源代码禁用后的启动、外置曲库、重启及服务退出检查。state 的一个旧测试在缺少组件的 CI 上仍期待消耗下载次数，已改成提供隔离的组件存在性夹具，并新增缺组件保留 WANTED/零次尝试的测试。最终以 PR 对应提交的 CI 为准。

Bilibili 限流、账号和资源限制仍可能使歌曲不可用，产品会有限回退并显示终态。跨机器安装信任、未参与开发的新用户试用、低性能机器与长期大曲库使用，不能由本机自动测试代替。当前自签名不代表所有 Windows 都信任；候选版供用户直接验收，再决定正式推广。
