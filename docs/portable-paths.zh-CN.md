# 目录迁移与相对路径

将程序和数据一起放在一个资料目录中时，优先使用 `musicserver.paths.json`。它放在桌面程序 `.exe` 旁边；直接运行 PowerShell 服务时，放在服务脚本所在目录。

例如目录结构为 `Project/MusicServer_Desktop/` 和 `Project/MusicSever_app/`，在前者保存：

```json
{
  "schema": 1,
  "app_home": "../MusicSever_app"
}
```

`app_home` 相对于配置文件所在目录解析。整个 `Project` 移到另一个文件夹或盘符后，程序仍能找到原数据。启动时的工作目录不影响解析结果。数据目录必须已经存在；路径失效或配置文件损坏时，程序显示原因并停止启动，保留现有数据。

可以用 `scripts/maintenance/set_portable_paths.ps1 -ConfigDirectory <程序目录> -AppHome <现有数据目录>` 生成配置。同一卷上的路径保存为相对路径；跨卷路径保留为绝对路径。已有配置需要检查后用 `-Force` 更新。脚本只写配置，不移动音乐或数据库。

桌面程序优先读取本地配置，然后兼容 `MUSICSERVER_APP_HOME`、注册表 `HKCU\Software\MusicServerRuntime\AppHome`，最后使用平台默认目录。旧环境变量或注册表指定的目录不存在时，也停止启动。只有没有自定义配置的首次启动可自动创建默认数据目录。环境变量和注册表中的相对路径以程序所在目录为基准，建议改用配置文件以明确基准位置。

PowerShell 的显式 `-AppHome` 参数优先于本地配置，供桌面程序传递统一的绝对路径，也供安装和测试显式初始化新目录。直接调用时，相对参数以脚本目录为基准。服务启动后，其内部路径都解析为同一个绝对目录。

音乐库设置中的相对路径以数据目录为基准。例如 `Music` 表示数据目录下的音乐文件夹，`../共享音乐` 表示相邻文件夹。通过设置接口保存目录时，同卷位置优先保存相对路径，跨卷位置保存绝对路径。现有绝对路径仍可读取。缺失的自定义音乐库保持不可用，程序不自动改用其他目录。

移动便携目录时，应连同配置文件、程序和相对路径指向的数据一起移动。独立安装在 C 盘、数据放在 E 盘的布局仍需要跨卷绝对路径。Windows 计划任务也保存启动位置，移动后需重新注册；应用正常启动会检查每日推荐任务的位置。仅修改路径设置不会迁移旧数据库中的历史文件引用，也不会合并两份数据库。
